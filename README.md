# toke-website

This is the source code for [tokelang.dev](https://tokelang.dev), the official website for the toke programming language. It contains all documentation, tutorials, and reference material for toke. The site is built using ooke, toke's native web framework, and compiles to a single binary that serves the site over HTTPS.

## About toke

> toke: a compiled language designed for LLM code generation, with a small grammar, one
> canonical form and compiler verification.

toke is a compiled programming language designed for LLM code generation. It has 14
keywords, a 59-character set, a backtrack-free grammar with bounded lookahead, and one
canonical form per construct, chosen by measurement in a 46-pattern catalogue and
reproduced by `tkc --min`. That makes generated code cheap to constrain during decoding,
cheap for a compiler to verify afterwards, and compact to emit. Token efficiency is one
measured property of toke, always reported with its tokenizer and its baseline, not the
whole claim.

*The one-liner and the paragraph above are reproduced word for word from the canonical
description,
[`docs/about/canonical.md`](https://github.com/karwalski/toke/blob/main/docs/about/canonical.md).
Every number published about toke comes from
[`docs/metrics-baseline.md`](https://github.com/karwalski/toke/blob/main/docs/metrics-baseline.md)
and nowhere else.*

## Website sections

- **Getting started** -- installation, hello world, project setup
- **Tutorials** -- step-by-step guides covering modules, control flow, collections, strings, error handling, and more
- **Language reference** -- syntax, semantics, and type system
- **Stdlib reference** -- standard library module documentation

- **Cookbook** -- real-world recipes (REST APIs, data pipelines, doc pipelines)

## Local development

You need the toke compiler (`tkc`) on your PATH.

```bash
# Generate self-signed TLS certs for local dev
make certs

# Compile and run the site server
make run
```

The server will start on `https://staging.tokelang.dev:443` (you may need a `/etc/hosts` entry pointing `staging.tokelang.dev` to `127.0.0.1`).

For plain HTTP on port 9080:

```bash
make run-http
```

## Content structure

```
main.tk            # Server entry point (ooke app) — the only toke source that is built
ooke.toml          # Site configuration
templates/         # Page templates (.tkt). One route per file: index.tkt -> /,
                   # roadmap.tkt -> /roadmap, docs/index.tkt -> /docs
content/           # Generated-page sources (roadmap.json) + docs content symlinks
sites/             # Source of the site-root files: llms.txt (read at startup by
                   # main.tk), robots.txt, sitemap.xml, the favicons and 404.html.
                   # NOT served directly — it was the vhost docroot until the
                   # vhost mechanism was removed (story 132.21); build_static.sh
                   # copies what has to be reachable into build/.
static/            # CSS, JS, images, the program-library JSON, the standalone pages
build/             # Gitignored. Generated by `make build` from static/ and sites/
pages/             # Route names for `ooke build` only (story 134.8): one
                   # /docs/<section>/<slug> page per pages/**/*.tk *filename*.
                   # The server never reads it — main.tk routes with
                   # http.servepages("templates";"templates"). The bodies are
                   # still pre-v0.3 and 13 of 24 do not compile; migrating them
                   # is story 132.17 / 134.2. Do not delete the tree: that
                   # deletes the ~195 documentation pages.
scripts/           # Generation, gate and deployment scripts
.github/           # CI workflow
```

## Checks

`make ci` runs everything a change must pass before it is deployed, and the CI
workflow runs the same targets:

| Target | What it protects |
|---|---|
| `make check-toke` | Every toke source the site is built from compiles under `tkc`. `main.tk` once sat at HEAD in v0.3 `=`-equality that the current compiler rejects, so the site could not be rebuilt from its own source. |
| `make check-roadmap` | `/roadmap` and the home-page milestones block still match `content/roadmap.json`, their single source. |
| `make check-llms` | `/llms.txt` still matches the canonical facts block in the compiler repo (`docs/about/canonical.json`, override the location with `TOKE_DOCS`). |
| `make build` | Rebuilds `build/` from committed sources. It is gitignored but the deploy rsyncs it. |
| `make check-build-fresh` | `build/` is not older than `static/`, `templates/`, `content/` or `sites/`. |
| `make check-routes` | Starts the server and asserts every route the repository defines answers 200. |

`scripts/deploy.sh` runs the same gates and rebuilds `build/` before it syncs
anything, so a deploy cannot publish a stale tree.

## Deploying

The deploy script cross-compiles for Linux and deploys to a remote server:

```bash
TOKE_DEPLOY_HOST=your.host \
TOKE_DEPLOY_KEY=~/.ssh/your-key.pem \
./scripts/deploy.sh
```

This emits LLVM IR locally, rsyncs it to the server, compiles a native binary with clang, and restarts the service. See `scripts/deploy.sh` for details.
