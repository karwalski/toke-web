About toke

A language built for the AI generation era.

What is toke?

toke is a compiled, statically-typed systems language with a compact syntax purpose-built for AI code generation. The language is designed so that a language model can write correct, idiomatic toke programs faster and with fewer tokens than equivalent programs in other languages — while still being readable and unambiguous to humans.

toke compiles to native machine code via LLVM. It has no garbage collector, a small runtime, and a rich standard library.

Design goals

Compact and unambiguous

Every syntactic construct in toke is short and has exactly one form. There are no optional keywords, no alternative spellings, no context-sensitive rules. A program token is always the same shape regardless of where it appears.

Compiled to native

toke programs compile directly to native binaries. No interpreter, no VM, no JIT warm-up. The compiler targets LLVM IR, giving toke access to mature optimisation passes and broad platform support.

Designed for AI code generation

Compact syntax means shorter prompts and fewer output tokens. Unambiguous grammar means a model is less likely to generate syntactically invalid code. A consistent standard library means fewer naming surprises. These properties combine to make toke a first-class target for LLM-driven development workflows.

Syntax overview

Whitespace

Whitespace separates tokens but has no other structural role — indentation, line breaks, and spacing between tokens are all equivalent. The compiler treats any run of whitespace as a single separator. You may format toke code however you like.

Statement terminator

Statements end with a semicolon ;. The semicolon is always required; there is no automatic semicolon insertion.

Modules

Every file begins with a module declaration: m=name;. Imports use the form i=alias:std.module; — the alias is the local name used to call into the module.

Functions

Functions are declared with f=name(params):returntype{body}. The return value of the last expression in the body is the implicit return; the explicit return operator is <.

Types

Built-in types include i64, i32, f64, bool, and str. Arrays use @(type) syntax. There are no nullable types — use an explicit optional wrapper from the standard library instead.

Status

toke is in active development. The compiler (Gate 1) is complete and self-hosting. Phase 2 is underway, covering the standard library, corpus, and toolchain.

  • Phase 2 — stdlib + corpus: in progress
